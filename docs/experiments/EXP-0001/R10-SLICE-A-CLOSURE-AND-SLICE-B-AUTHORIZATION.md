## 4. Prospective Slice B implementation authorization

After this record is reviewed and merged, Slice B may add only the minimum code, within the existing `experiments/exp-0001/crates/exp1-record-format` package, needed to:

1. accept explicit deterministic, already-validated caller-supplied candidate values;
2. construct a B0 entry and account for declared logical bytes and the construction/insertion path;
3. reserve vector capacity before publication, assign the next nonzero process-local sequence on the single owning thread, move the entry once into the vector tail, and expose only a provisional D0 result;
4. retain only the B0 in-memory state necessary for that lower-bound mechanism; and
5. add deterministic correctness tests proving unique strictly monotonic process-lifetime assignment, preserved input identity/cardinality/order, and no invention or duplication across success and pre-publication rejection/overflow paths.

The API, tests, and documentation must label every B0 entry, observation surface, and acknowledgement **D0, process-local, provisional, and noncanonical**. Process loss discards the vector, counter, and reconciliation state. Memory state must never be described or promoted as authoritative canonical history. Tests may use fixed literal candidates; they must not invent or imply the unresolved BLK-006/007 benchmark generator.

This authorization reuses the existing package because a new crate would broaden R9 without necessity. It permits no manifest or lockfile change and no new dependency, feature, build script, binary, example, benchmark target, fixture, generated source, CI workflow/action/permission, toolchain, target, edition, resolver, profile, flag, package, workspace member, directory layout, or production `/crates/` file. Existing R9 format, Clippy, locked/offline test, and documentation checks remain the validation gate. Any need to expand those boundaries suspends authorization and requires a prospective superseding governance decision; BLK-020/026/027 are not silently broadened.

The immutable approval state for `EXP-0001-R10/slice-b-implementation-v1` is this record's eventual merge commit on `main`. Authorization is ineffective on this branch. A review finding of a contradictory B0 operation, ambiguous accounting definition needed by the implementation, or required boundary expansion suspends work rather than permitting an inference.
